# CCCP 动态专家启动器使用手册

## 1. 快速开始

1. 保持发行目录结构完整，不要单独移动 `CCCP-Launcher.exe`。
2. 将 CCCP 模型放入同目录的 `models` 文件夹；也可以在“设置 → 模型目录”中添加其他磁盘位置。
3. 双击 `CCCP-Launcher.exe`。程序只打开原生桌面窗口，不会自动打开外部浏览器；它会自动选择内置环境，不需要安装 Python、Miniconda 或其他依赖。
4. 在首页选择模型；MoE 模型再选择专家配置，Dense 模型直接点“一键启动”。启动器会自动预检；“预检”按钮仅用于提前查看容量。
5. 模型加载期间会自动切换到终端页，显示阶段、进度和错误；加载完成后进入聊天页。

CPU v192 算子已经预编译，正常情况下直接加载；只有预编译文件损坏或 Python ABI 不匹配时才走本机应急编译。NVIDIA/AMD 第一次在新显卡上启动时，可能针对当前架构进行一次离线编译。编译器已经随包提供，不会联网下载，也不需要安装。启动器会自动切换到终端页，以活动进度条、后端名称、已用时间、5 秒心跳以及 Ninja/编译器原始输出持续显示状态。编译产物保存在本机应用数据中的稳定缓存，移动启动器或升级版本后仍会复用；终端显示 `cccp-op-cache hit` 时不会再次调用编译器。只有显卡架构、Torch/CUDA/ROCm 版本或算子源码变化才会生成新缓存。

## 2. 目录说明

| 目录 | 用途 |
|---|---|
| `models` | 默认模型目录，每个模型目录应包含 `cccp.json` |
| `<模型>/profiles` | 与该模型绑定的专家配置 |
| `profiles/user` | 手动导入的共享配置 |
| `data/corpus` | 上传后持久保存的训练语料 |
| `data/training` | 训练进度、专家热力图和扫描结果 |
| `runtime` | CPU、NVIDIA CUDA、AMD ROCm/HIP 独立环境 |
| `engine/CCCP-Engine` | 推理引擎和加速算子 |

删除模型、配置或语料前，启动器会要求确认。模型权重不会被训练页修改。

## 3. 模型与专家配置

配置文件记录模型名称、版本、格式、模型指纹、固定权重体积和每个专家编号。导入配置时，启动器只会把它显示在指纹匹配的模型下。

同时选择多份配置时，重复专家只计算和加载一次。没有配置时可以选择“全量专家加载”，这表示保留模型全部专家参与路由，并不减少专家或修改模型原生 top-k。

如果模型清单声明为 Dense VQ，启动器会直接加载完整模型。Dense 没有动态专家，也没有专家编号、热力图或专家配置；首页会隐藏配置选择，训练页会明确提示“该模型无需训练”。模型架构来自 `cccp.json`，不是根据文件夹名称写死，因此后续采用相同清单协议的 Dense 模型可以复用同一运行链路。

首页、配置库卡片和组合汇总统一显示“配置总驻留”，即 Dense、共享专家和所选动态专家权重之和。实际运行还需要上下文缓存、工作区和程序内存，因此预检显示的预计 RAM/显存通常高于配置总驻留：

- CPU 模式当前空闲内存不足：先关闭浏览器、游戏或其他占内存程序；仍不足时才使用磁盘映射。
- GPU 预检会分别显示“CUDA 最低工作集”和“全速建议显存”。通常前者包含 Dense、当前上下文与 CUDA 工作区；Kimi 在小显存卡上可把 Dense 放在主机内存，因此最低值只表示 RAM-Dense CUDA 基础工作区与最小专家块。全速建议值要求 Dense 回到显存并保留有用的专家热缓存，但不要求整份专家配置全部塞进显存。
- 显存低于全速建议值、但仍高于最低工作集时显示黄色提示：自动缩小 GPU 专家块，完整专家配置驻留主机内存，按剩余显存分批执行；专家数量与模型 top-k 均不改变。
- 预检会先把上下文从 4096 自动降到 2048、1024、512 以适应小显卡；Kimi RAM-Dense 档直接使用保守的 512 token。如果仍低于 CUDA 最低工作集，则显示红色提示并询问是否改用 CPU，不会以减少专家换取启动。
- 只有完整专家配置连主机内存也放不下时才降级到磁盘映射，并明确提示速度会明显下降。
- 红色提示是运行风险，不会偷偷删除专家。

## 4. 从语料生成配置

训练页只统计真实路由，不生成新模型，也不改写权重。

本节仅适用于带动态专家路由的 MoE 模型。Dense 模型没有可扫描的专家路由，选择后不会显示开始扫描按钮。

1. 选择目标模型。
2. 上传 `.jsonl` 或 `.txt` 语料；文件会复制到 `data/corpus`，以后可复用或删除。
3. 选择自动内存策略，或强制磁盘模式。
4. 开始扫描。页面会自动进入终端；完整的 system、user、assistant 上下文都会计入，使用 4096-token 分块执行 teacher-forcing prefill，不额外生成回答。
5. 每完成一个 4096-token 整块，任务详情会更新中间热力图；此时仅用于观察分布，不能提前生成半成品配置。
6. 全部扫描完成后调整覆盖率，观察专家数量、动态专家体积、固定权重与预计总驻留。
7. 填写配置名称与用途说明，点击“保存配置”。启动器会把模型身份、专家编号和精确体积写入模型对应的配置库，不会复制或修改模型权重。

正式配置建议至少扫描 500,000 token；也可以输入较小的 4096 倍数先验证流程。耗时取决于 CPU、磁盘和模型规模，系统会按当前可用内存自动选择批量，不需要用户调整算子参数。每层会把命中同一专家的 token 聚合后批量计算；该通用路径也用于正常聊天的长提示词 prefill。进度保存在 `data/training`；界面显示当前对话、块和层。运行中的任务可以在卡片上停止。

## 5. 聊天与停止生成

输入框会随内容自动增高，发送后恢复默认高度。生成期间“发送”会变成“停止”；停止后已生成内容仍会保留。最后一轮消息可以回退，即使 Assistant 尚未回复也能恢复输入。

“思考”文字按钮会打开强度选择气泡。启动器会读取当前模型声明的能力，只显示模型真正支持的档位；“自动”采用模型声明的默认强度。思考内容折叠保存在当轮气泡中，下一轮只发送正式回答。重复惩罚用于减少复读，存在惩罚用于降低已出现 token 再次出现的倾向。速度、首 token 时间、KV 前缀复用/冷启动和上下文处理信息显示在对应 Assistant 气泡下方。

## 6. OpenAI 兼容 API

模型启动后，API 页会显示 Base URL、模型 ID 和调用示例。第三方程序使用 `/v1/models` 与 `/v1/chat/completions`；`/api/` 是启动器自己的管理接口。

设置页可以启用 Bearer API Key，并生成新 Key。Key 仅保存在本机 `data/settings.json`，不会写入或导出专家配置。运行中更换 Key 前先停止模型。

## 7. CPU、NVIDIA 与 AMD

- CPU：所有电脑的默认回退路径，自动使用物理核心、Q4 执行映像、码本缓存和融合算子。
- NVIDIA：需要 RTX 20 系或更新的兼容显卡及已安装的 NVIDIA 驱动；CUDA 环境已随包提供。首次启动会自动读取当前卡的架构并编译：RTX 2060/2070/2080=SM75，RTX 3060/3070/3080/3090=SM86，RTX 4060/4070/4080/4090=SM89，H20/H100=SM90，RTX 5060/5070/5080/5090=SM120；同代 Ti、SUPER 和 Laptop 型号自动归入实际架构，结果缓存后直接复用。
- AMD：需要受随包 ROCm/HIP 版本支持的 AMD 设备和驱动；不使用 DirectML。

GPU 启动后可以在终端核对真实执行器。NVIDIA 会显示相应的 `cuda.*` 融合执行器；AMD 全显存 TokenGraph 路径必须显示 `hip.tp1-token-graph` 并持续增加 Graph 提交计数。若仍显示 `cuda.packed_moe_topk_fused`，说明目录混用了旧引擎文件，应停止程序并重新解压完整发行包，不要覆盖零散文件。

启动器会自动检测可用设备。检测失败的环境会置灰并显示原因，不需要手动填写环境路径。

## 8. 更新、备份与故障处理

更新检查在后台进行，网络不可用不会阻塞启动。发现新版本时会显示来源和下载入口，也可以忽略该版本。

建议备份：

- `<模型>/profiles` 与 `profiles/user`
- `data/corpus`
- `data/settings.json`

常见问题：

- 找不到模型：确认模型目录内存在 `cccp.json`，然后在设置中添加它的上级目录。
- 配置不显示：模型指纹不匹配，不能强制混用。
- 加载很慢：查看终端是否正在磁盘映射；关闭占内存程序，模型和缓存尽量放在 SSD。
- 算子编译失败：不要删除 `toolchain`、`runtime` 或 `engine`，并确认安全软件没有隔离其中的 DLL/PYD。
- 编译看似较久：终端应持续显示“编译中”、已用时间和每 5 秒心跳；只要心跳更新，编译器仍在工作。失败时不要关闭错误页面，终端会保留具体编译命令和原因。
- 页面似乎未更新：完全退出旧启动器后重新双击 EXE。

## 9. 使用边界

发行包只包含推理运行时，不包含模型权重、特定模型预设或 CCCP 量化/训练框架。GPU 驱动由操作系统提供，无法打入便携目录。不同硬件的速度差异很大；容量提示与速度估算用于预检，不是性能承诺。
